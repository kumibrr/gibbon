# Gibbon Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Go CLI, `gibbon`, that manages multirepo feature worktrees laid out as `workspace/<feature>/<repo>` over primary clones in `workspace/base/<repo>`.

**Architecture:** Thin cobra commands in `internal/cli` call pure operations in `internal/ops` that return per-repo results. `ops` composes `internal/git` (subprocess wrapper), `internal/workspace` (locate + TOML state), `internal/discover` (filesystem-derived repo/feature models) and `internal/pool` (bounded parallelism). Rendering lives in `internal/output`.

**Tech Stack:** Go 1.27 (mise-pinned), `github.com/spf13/cobra`, `github.com/BurntSushi/toml`, system `git` binary, `text/tabwriter`. Tests use real git in `t.TempDir()`.

**Spec:** `docs/superpowers/specs/2026-09-14-gibbon-design.md`

## Global Constraints

- Module path `github.com/kumibrr/gibbon`; Go pinned in `.mise.toml` to `1.27.1`.
- `ops` never prints and never reads flags; it returns data.
- Membership and repo list are derived from the filesystem; only base branch overrides, branch template, workers, and per-feature metadata are stored.
- Dirty = `git status --porcelain` non-empty (untracked included, ignored excluded).
- Cross-repo commands run all repos, then exit non-zero if any failed.
- Feature names: no `/`, not `base`, not dot-prefixed, valid git ref component.
- Real git in tests; no mocks of git.
